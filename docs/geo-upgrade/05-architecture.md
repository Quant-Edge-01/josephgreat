## Recommended names from the master prompt

/services can redirect to /toronto-marketing, /about to /about-joseph. Keep the existing /pricing → /#offer redirect for compatibility; link new pages directly to /affordable-marketing-toronto. The proposed alternate industry names add no new intent; if adopted as aliases, redirect them to existing industry routes and keep aliases out of the sitemap.

No parallel canonical page containing the same pricing or industry prose. No city-by-city route grid.

## Navigation and visuals

Homepage hierarchy, jar, portrait, music and global palette stay intact. Extend the existing service hub with direct service links; keep quiet footer links. Link every service to the relevant cases and back from cases. The case index links all four cases in server HTML.

New pages use the existing type and colours, one concise first paragraph, compact FAQ, an evidence image, a contact link and the existing three-free-ideas CTA. Avoid adding a second site navigation system or a long keyword footer.

New informational pages open directly for all users. No bot-specific rendering. Preserve the existing entrance on current routes unless the owner separately approves changing it.

## Ten required answers on new service pages

Use concise visible sections rather than a repetitive ten-item questionnaire. State exactly which deliverables are candidates for the written scope; do not sell unspecified quantities as guaranteed inclusions. A website page can use this site as a work sample, but cannot claim it improved client conversion without evidence.
